# Image Palette Studio 圖片色票工作室：概念與實作規格

> 更新日期：2026-09-18。依目前工作目錄的程式碼、介面、測試與部署設定整理。
> 本文件整併原始構想及歷次進度，以各節「目前實作」為現況；未完成需求集中列於第 9 節。程式碼已有實作不等於已通過遠端部署或實機驗收。

## 1. 專案定位

Image Palette Studio 是以瀏覽器為工作環境的圖片取色與配色工具，提供「圖片提取」與「憑空生成」兩條工作流程，再將色票用於照片色票卡、CSS 漸層與多格式匯出。

核心用途包含照片／劇照色彩分析、品牌主色延伸、moodboard 製作及設計與前端開發之間的色彩交付。所有圖片處理、色彩計算與檔案生成均於本機瀏覽器執行，無需帳號、API Key 或後端服務。

目前版本資訊為 `package.json` 的 `0.2.0`。已依專案擁有者選擇採用 [MIT 授權](../LICENSE)，發布封裝亦包含授權檔。

## 2. 架構原則與部署條件

- **零 AI 模型**：使用色彩轉換、聚類、色差與幾何計算，不依賴神經網路。生成與部分風格含隨機取樣，因此不保證相同輸入每次產生相同色票。
- **純靜態網站**：原生 HTML、CSS、JavaScript 即可執行；不依賴 SSR、Serverless Functions、資料庫或第三方付費 API。
- **GitHub Pages 足以承載全部核心功能**：支援網域根目錄及 `/image-palette-studio/` 子路徑，資源、manifest 與 Service Worker 使用相對部署路徑。
- **本機資料處理**：照片、色票、鎖定與模式工作狀態保存在頁面記憶體；重新整理後清空。主題與語言偏好另存於 localStorage。
- **離線 PWA**：首次在 HTTPS 或 localhost 成功快取後，可離線載入本機圖片、配色與匯出。使用系統字型，核心操作不需要第三方網路資源。
- **效能界線**：圖片取樣、Canvas 預覽與匯出設有縮放或尺寸限制；已建立 12MP／24MP 合成圖片的桌面與手機模擬基準，詳見 [效能報告](benchmarks/README.md)；尚非實機效能保證。

## 3. 雙軌工作流程

### 3.1 共用操作與狀態

開站預設進入「憑空生成」，採用類比調和、原始風格並立即產生 5 色。色票數可切換為 **3／4／5／6／8 色**。

Space／R、重新生成按鈕與手機浮動「重新配色」按鈕會保留仍存在槽位的鎖定色。文字輸入或其他互動控制項取得焦點時，快捷鍵避免干擾原有操作。生成模式另可按 A 新增主色錨點。

兩種模式分別保留本次頁面工作階段的色票、鎖定、色數、選取槽位及畫布設定；圖片模式另保留取色錨點。切换模式可回到先前工作，載入新圖則重設圖片取色內容，保留生成模式工作。

### 3.2 模式 A：圖片提取

**輸入與自動提取**

- 支援本機選檔、拖放與剪貼簿圖片貼上；接受 JPEG、PNG、WebP、GIF，檔案上限為 20 MiB（介面標示 20MB）。動畫輸入不提供逐格編輯或動畫匯出。
- 以 K-means++ 建立最多 32 個群集候選，從照片取樣像素尋找代表位置，再用 CIELAB D65 的 CIE76 ΔE 進行差異篩選。
- 優先選擇亮部、暗部、鮮豔色與中性色，再補代表色；重新生成優先探索尚未顯示的候選色，候選不足時仍可重複。
- 保留照片中的黑白與低彩度色，不以照片外的隨機色補足。低色彩圖片可能出現重複色，全透明或沒有可用取樣像素的圖片會顯示錯誤。
- 圖片模式不套用風格投影，風格面板隱藏。一般色票取自原圖像素或平均取樣；使用者主動以螢幕滴管指定的外部色則會另外標示。

**原圖取色錨點**

中央「原圖取色」區顯示完整照片及編號錨點，每個錨點對應右側同編號色槽。錨點保存原圖座標，獨立於輸出預覽的裁切與縮放。

- 滑鼠或觸控拖曳即時更新對應色槽與合成預覽，放開即完成。
- 可先選取色槽編號，再點擊原圖移動對應錨點；鎖定槽位不接受移動。
- 拖曳時顯示放大鏡；方向鍵移動一個原圖像素，Shift＋方向鍵移動十個像素。
- 支援單像素、3×3、5×5 平均取樣；邊緣範圍限制在原圖內，透明部分不以黑色混入。
- 可選「邊緣吸附」（預設關閉）：點擊或拖曳時，在附近 6 個原圖像素內依局部亮度梯度與距離尋找邊緣，排除透明像素；平坦區域維持原位置。方向鍵不吸附，保留逐像素微調能力。
- 改變色數時保留尚存在錨點的位置、色值與鎖定，新增槽位優先採用尚未佔用的候選位置。
- 瀏覽器支援 `EyeDropper` 時，「螢幕滴管」可覆寫目前選取且未鎖定的色槽。API 不提供原圖座標，因此保留位置並標記外部色；再次拖曳會恢復照片取樣。不支援時仍可使用原圖取色。

**帶入生成模式**

圖片模式有鎖定色時，可將它們帶到「憑空生成」作為主色錨點，再延伸新配色。帶入數量上限為目標色票數減一，超出會提示；此操作會以帶入主色更新生成模式的錨點並清除其原有鎖定。

### 3.3 模式 B：憑空生成

提供兩種演算法入口：

| 演算法 | 目前行為 |
| :--- | :--- |
| Chaos | 在安全明度範圍內隨機生成；有主色錨點時保留主色，其他槽位以差異色補齊，不保證色相接近主色。 |
| Harmony | 優先以第一個主色錨點，其次第一個鎖定色，最後隨機色作為基準，依選定調和方式展開。 |

主色錨點接受 HEX（3／6 碼）、`rgb(r, g, b)`、`hsl(h, s%, l%)` 或原生色盤。主色錨點是指定色值，與圖片模式的座標錨點不同；最多可新增色票數減一個。

可選「60-30-10 配色配置」（預設關閉）：第一槽為主底色、第二槽為次要色、最後一槽為點睛色，其餘為中性色；3 色模式僅有底色／次色／點睛色。純色票畫布扣除間隙後依 60%／30%／10% 分配寬度，30% 由所有次要／中性色槽均分，PNG／JPG／SVG 同步使用此幾何配置。

風格與色彩角色處理後會合併使用者主色與鎖定色，維持其精確色碼。鎖定槽位優先，主色依序寫入可用未鎖定槽位；空位不足時僅放入容得下的主色。

## 4. 色彩運算與風格

### 4.1 目前管線

```text
圖片 → 取樣／K-means++ → 原圖代表位置／手動取樣 ─────┐
                                                  ├→ 保留鎖定色 → 最終色票
主色或隨機基準 → Chaos／Harmony → Oklch 風格／可選角色 ┘
                               → sRGB 色域映射 → 合併精確主色

最終色票 → 色槽／對比檢測／CSS 漸層／Canvas 合成／匯出
```

`basePalette` 保存未投影色票，切換風格時從原始資料重新計算，避免累積投影失真；「原始」可還原基底色票，但仍保留使用者固定色。過期的非同步提取結果不覆寫新工作，生成失敗會提示並保留既有結果。

目前色差使用 Lab，基礎調和使用 HSL，風格及角色投影使用 Oklch。`gamutMapOklch()` 在固定 L／h 下以二分搜尋降低 C，直到進入 sRGB 色域，避免直接逐通道裁切造成色相偏移；最終 HEX 仍有 8-bit 量化誤差。圖片取色與使用者指定的精確色碼不經此風格管線。

### 4.2 五種調和

| 模式 | 基礎生成規則（套用風格前） |
| :--- | :--- |
| 類比色 | 色相在基準 ±30° 內展開，搭配明度分布與小幅 S／L 隨機變化。 |
| 互補色 | 0°／180° 色相族，以明度及飽和度變體補足槽位。 |
| 分裂互補 | 0°／150°／210° 色相族。 |
| 三角色 | 0°／120°／240° 色相族。 |
| 單色調 | 固定色相與飽和度，明度由 15% 至 90% 等距展開。 |

60-30-10 角色投影在基礎調和與風格後套用，底色偏亮低彩度、次色偏中暗、過渡色偏中性、點睛色提高彩度；風格 L／C 邊界及固定色優先，因此特定風格或固定色可能限制角色的明暗／彩度差異。此配置僅用於生成模式，圖片模式仍保留來源色。

### 4.3 風格預設

提供「原始」及十種風格。以下為 `styles.js` 的 Oklch 主要邊界，L 與 C 使用實數值，h 以角度表示；色域映射可能進一步降低 C，輔色分支可能使用其他 h／C。

| 風格 | 主色相 h | 彩度 C | 明度 L | 特殊處理 |
| :--- | :--- | :--- | :--- | :--- |
| 莫蘭迪 | 全色相 | 0.02–0.07 | 0.55–0.80 | 低彩度灰調 |
| 馬卡龍 | 全色相 | 0.04–0.10 | 0.85–0.96 | 高明度粉彩 |
| 大地色 | 40–85° | 0.04–0.13 | 0.40–0.72 | 棕赭色域 |
| 美拉德 | 35–75° | 0.05–0.16 | 0.28–0.82 | 明度 0.28／0.45／0.63／0.82 階梯 |
| 多巴胺 | 全色相 | 0.18–0.30 | 0.65–0.85 | 高彩度 |
| 薄荷曼波 | 150–175° | 0.06–0.14 | 0.76–0.92 | 每第三槽使用輔色 |
| 波普 | 25／90／145／195／265／325° | 0.20–0.32 | 0.55–0.80 | 以環狀角距映射色相 |
| 森林系 | 110–160° | 0.035–0.13 | 0.35–0.73 | 末槽樹皮棕輔色 |
| 海洋系 | 210–265° | 0.05–0.16 | 0.40–0.85 | 末槽亞麻色輔色 |
| 礦石系 | 30–60° | 0.04–0.12 | 0.45–0.73 | 末槽冷灰輔色 |

主色錨點及鎖定色不接受風格改色。與固定色不相容的風格會停用並灰顯；若目前風格變成不相容，切回「原始」。相容性是來源色與 Oklch 投影結果之 CIE76 ΔE 門檻的產品啟發式判斷，不代表視覺不可辨識或正式色彩標準。部分風格的輔色會呼應第一個鎖定色的色相。

## 5. 色票卡排版與合成

### 5.1 畫布比例與照片位置

提供原始、1:1、4:3、3:2、16:9、2:1、9:16。固定比例指完整輸出畫布，照片配置在版型分配的照片區。

「原始」依照片與版型向外配置色票區，並非保證合成後仍等於照片寬高比；純色票模式的原始畫布為 1200×600。一般場景以 1200px 寬為基準建立。

照片可選置中裁切或完整留白；裁切模式可在合成預覽拖曳調整位置。原圖取色座標不因裁切改變。

### 5.2 七款版型縮圖

七款預設涵蓋原構想的六類版型，側邊直條分為左右兩款。縮圖由實際場景渲染產生，約 40×30px；色數選擇與主色票數同步，所有版型均支援 3／4／5／6／8 色，縮圖跟隨重繪。

| 版型 | 色票佔比範圍 | 預設 | 比例計量 |
| :--- | :--- | :--- | :--- |
| 底部通欄 | 8–40% | 25% | 畫布高度 |
| 左側直條 | 8–35% | 20% | 畫布寬度 |
| 右側直條 | 8–35% | 20% | 畫布寬度 |
| 四角散佈 | 15–45% | 30% | 照片外框面積 |
| 標籤引線 | 25–50% | 35% | 畫布寬度 |
| 並排色條 | 30–60% | 50% | 畫布寬度 |
| 色票主導 | 60–85% | 70% | 畫布高度 |

引線版型可逐槽編輯最多 40 字的標籤，預設採近似色名。引線對應照片錨點；来源落在裁切範圍外時以虛線與「裁切外」標示，外部色則標示「外部色」而不虛構來源。依專案擁有者指示，文字維持現有系統字型設定，不新增手寫字型或字型選擇器。

無照片的生成模式使用純色票橫列，比例、間隙與標籤仍生效，七款照片版型不會各自產生不同的純色票構圖。

### 5.3 視覺設定

色塊間隙可調 0–16px，圓角可調 0–12px；標籤可關閉、放在色塊內或下方，內容可切換 HEX／RGB。內嵌文字依背景選擇黑白字，色票卡背景使用固定淺暖色，不隨介面主題改變。

`CanvasRenderer.buildScene()` 產生共用場景資料，預覽、高解析度點陣圖與 SVG 均以此建立，保持幾何、裁切、色塊及文字配置一致。

## 6. 對比檢測、色盲預覽與匯出

### 6.1 色彩檢測

- 色票標籤使用相對亮度及對比計算；文字對比面板顯示一般文字的對比值與 AA／AAA／未通過等級。
- 面板支援手動指定前景／背景色，或自動選出 CIE76 ΔE 最大的兩色，再以 HSL 明度較低者作為前景。自動選取依據是色差，不保證選到最高 WCAG 對比值。
- 憑空生成模式可鎖定對比等級（AA／AAA）：鎖定後，每次生成、重新生成或換色數都會重新套用自動配對規則，若對比不足會在非鎖定、非主色錨點的那一槽沿目前風格的 Oklch 明度邊界微調拉開差距；兩槽都是鎖定色或錨點色則維持原色不調整。無法在目前明度邊界內達標的風格會停用灰顯，與固定色不合拍風格的既有機制共用同一套停用邏輯。此鎖定只影響憑空生成，圖片提取模式一律保留照片原色，鎖定控制項在該模式停用。
- SVG 矩陣濾鏡提供紅色盲、綠色盲、藍黃色盲與全色盲近似預覽，作用於照片、色票、縮圖及漸層等色彩區域。
- 模擬不改寫色票資料，也不烘焙進下載檔案；對比面板不是整個網站的無障礙合規認證。

### 6.2 匯出格式

| 格式 | 目前輸出 |
| :--- | :--- |
| PNG | 重新渲染完整合成，無損點陣圖。 |
| JPG | 完整合成，JPEG 品質參數 0.95；屬有損格式。 |
| SVG | 照片以內嵌點陣圖保存，色塊、圓點、引線與文字為向量元素；包含裁切資訊，不將照片自動向量化。 |
| ASE | 以 DataView 產生 Adobe Swatch Exchange 色票二進位檔。 |
| ACO | 產生 Adobe Color 色票二進位檔。 |
| JSON | Design Tokens 形式，包含 `$type: color`、sRGB components、alpha、HEX 與描述。 |
| CSS | `:root` 色彩變數。 |
| Tailwind | v3 的 CommonJS 配色設定，或 v4 的 `@theme` CSS。 |

PNG／JPG 提供 1×／2×／4× 倍率並顯示預計像素尺寸。輸出任一邊超過 16,384px 或總像素超過 48,000,000 時會拒絕並提示降低倍率或改用固定比例；提高倍率不會補回原照片缺少的細節。

CSS、JSON 與 Tailwind 均有程式碼預覽及複製。漸層提供 90° Linear 或中央圓形 Radial，依色票順序等距分布色標並可複製 CSS。

## 7. 主題、語言與 PWA

主題提供淺色、暗色及跟隨系統三個圖示選项，採滑動 Pill 呈現；預設淺色。localStorage 記憶偏好並跨分頁同步，系統模式即時監聽作業系統變更，儲存受限時仍可切換。

頂部語言選單提供繁體中文、英文、日文、韓文、泰文、越南文與西班牙文，預設繁體中文。`locales.js` 提供翻譯，`i18n.js` 綁定既有文字與無障礙屬性，支援動態訊息與參數。localStorage 記憶語言並跨分頁同步，儲存受限仍可切換；所有語言資源在本站並納入離線快取。

切換語言不改寫照片、色票、主色輸入、使用者自訂引線標籤或匯出程式碼。色票卡目前仍保留既有自動色名與使用者標籤內容；介面翻譯與卡片內容分開處理。

PWA 已有相對路徑 manifest、192／512px 圖示、Service Worker、安裝入口與離線狀態。Chrome／Edge 在支援安裝提示時顯示入口，其他環境依瀏覽器能力處理；`file://` 不提供 Service Worker 離線快取。

快取僅包含本站程式及圖示，不保存使用者照片或匯出檔。新版本快取完成會提示使用者關閉本站所有分頁／已安裝視窗再開啟，避免強制重新整理造成工作遺失。

## 8. 技術結構、執行與驗證

### 8.1 實際技術棧

目前使用原生 JavaScript 全域模組與自訂 CSS，未採用最初建議的 Vue／React、Vite、Tailwind CSS、colord、Color Thief、ase-utils 或 vite-plugin-pwa。Tailwind 是匯出格式選項，不是本站 UI 框架。

| 檔案／目錄 | 職責 |
| :--- | :--- |
| `index.html`、`css/main.css` | 介面、響應式配置與視覺樣式 |
| `js/app.js` | 狀態、模式切換、生成管線與事件整合 |
| `js/core/extraction.js`、`harmony.js`、`styles.js` | 圖片提取、調和與風格投影 |
| `js/core/canvas-renderer.js`、`export-engine.js` | 共用場景、點陣／向量渲染及檔案輸出 |

### 8.2 本機執行與發布

執行網站不需要安裝 npm 相依套件，可用 VS Code Live Preview 或其他靜態 HTTP 伺服器開啟 `index.html`。若已安裝 Python，可執行 `python -m http.server 8000`。

測試與發布封裝使用 Node.js 22 以上：

```sh
npm ci
npm test
npx playwright install chromium firefox webkit
npm run test:browser
npm run build
```

建置複製靜態資源至 `dist/`，以快取資源內容雜湊產生 Service Worker 版本，並建立 `.nojekyll`。直接發布原始碼時，更新資源須同步調整 `sw.js` 的 `VERSION`；新增必要資源須加入 `ASSETS`。

GitHub Pages 發布步驟：

1. 將專案與 `.github/workflows/pages.yml` 提交並推送至儲存庫的 `main`。
2. 在儲存庫 Settings → Pages → Build and deployment 將 Source 設為 GitHub Actions。
3. 推送 `main` 或手動執行 Test and deploy Pages。流程安裝依賴、執行 Node 與 Chromium／Firefox／WebKit 測試、封裝並發布 `dist/`；Pull Request 僅測試，不發布。
4. 在部署工作輸出的實際網址驗收子路徑資源、圖片上傳／拖放／貼上、配色與鎖定、各版型、所有匯出及離線重新載入。

實際 Pages 驗收仍為必要條件；僅有本機測試、工作流程設定或已推送原始碼，不代表部署完成。
